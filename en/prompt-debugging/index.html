Debugging a Prompt

Locate the faulty layer before rewriting adjectives, whether input, constraint, model or randomness.

Locate, then rewrite

When a generation misses, the reflex is to add adjectives. A faster move is to identify the layer that failed: the input itself, the way constraints are written, the model's capability, or plain randomness. Each layer needs a different repair; fixing the wrong one only lengthens the prompt.

Four layers

LayerSymptomsCheck firstAction
InputDisplaced lyrics, irrelevant referenceText encoding, audio length, formatUse clean input and a shorter excerpt
ConstraintsTempo drift, wrong ensemble, missing sectionsConflicting rules, placement too lateCut to three core rules, add back one by one
ModelLong form collapses, language unsupported, texture ceilingWhether the task exceeds public capabilityGenerate in parts, change tool type or model
RandomnessSame prompt, very different resultsSeed, version, candidate countFix the seed and sample several times

Order of checks

1. Rerun the same prompt unchanged twice to see whether variance explains it. 2. Fix the seed and run again; does the fault persist. 3. Strip every modifier, keep tempo, ensemble and form, then add items back. 4. Swap in a shorter, cleaner input to rule out the material. 5. Try the same job in a different tool class to test the capability boundary. 6. Log each change and move one variable at a time.

The order controls cost. Changing models is expensive; adding adjectives is cheap and buries the cause deeper.

A log worth keeping

  • Full prompt and version number
  • Model name, version and date
  • Seed and candidate count
  • Input file and duration
  • The single change made this round
  • The fault and where it appears
  • Whether it reproduces

Without a log, debugging becomes memory. Anything compared more than three times needs a sample you can replay, or the next round repeats a hypothesis already eliminated.

When to change the method

Long forms that keep collapsing, diction that never passes in the target language, exact harmony that will not land: these are not prompt problems. More words only crowd the constraints. Generate in parts, switch to a symbolic tool, or treat the output as raw material. Debugging ends in a change of method, not a longer prompt.
